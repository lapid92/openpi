## Single signal and frozen identities
At the first post-stabilization observation only, use the exact fixed-arm initial standard-normal noise z and frozen policy. The production flow integrates from t=1 to t=0. Compute v1=v(z,1;o), z_mid=z-0.5*v1, and v_mid=v(z_mid,0.5;o) with the existing two-step cached trace; both evaluations share the observation prefix. This is a separately compiled diagnostic trace; exact internal equality of its first velocity to the public production sampler is not assumed. Production output parity and the separate cached/public final-action tolerance are tested explicitly. The only primary score is RMS(v_mid-v1)/max(RMS(v1),1e-6). RMS is over all ten action-horizon positions and first seven action coordinates in normalized model space, including the gripper; cast velocities to float32 before subtraction/square/reduction. Higher scores predict rescue. No direction reversal, alternate normalization, quantile clipping, epsilon tuning, or score fitting. Reject nonfinite inputs, intermediates or scores; preserve errors and stop. The RMS denominator safeguard makes a zero/zero score zero. This is a velocity-change diagnostic, not a calibrated error probability.

Save full z, midpoint, velocities, first hidden features, tensor dtypes, score components, noise and observation hashes and raw-file hashes. Existing frozen residual head yields initial log-sigma and sigma at t=1 from first features, with its unchanged checkpoint/metadata identity. Higher sigma is the prespecified comparison; no calibration or fitting. Metadata comparator ranks severity descending, with standard all tied; axes are descriptive strata with no fitted ordinal ordering.

## Observational implementation and cost
Leave production public fixed-step sampling and simulator actions unchanged. Run an isolated probe after production inference at chunk zero in every fixed arm; it uses explicit noise and an independent constant JAX key and cannot advance production or simulator RNG. The safe implementation recomputes the first velocity: it costs TWO extra velocity evaluations, one observation-prefix computation and one residual-head evaluation per episode. Count both probe evaluations in actual and primary hypothetical selection accounting. A shared-first-velocity implementation could theoretically need only one extra evaluation, but is neither implemented nor credited.

Fixed arms are 1,2,4,10 at every action chunk, identical initial states/noise streams within cases. Every arm records the probe independently for reproducibility; only the one-step arm's initial score is used for ranking, after equality audit. No later-observation aggregation. Actual study expense includes all four fixed rollouts, all probe calls, preparation/warmup/parity calls separately, prefixes, head calls and synchronized latency. No wall-clock speedup claim.

## Extra-compute budgets
Let C_i=ceil(declared maximum policy action steps for case i / ten replan steps). These task-metadata horizon caps are known at the start, independent of success/observed episode length. Baseline cap C=sum C_i. At budgets B=25%,50%,75%,100% extra cap, reserve2N probe evaluations for the flow signal,1N for the frozen-sigma comparator's isolated first-feature evaluation,0 for metadata. Rank descending within each benchmark; select the largest contiguous prefix whose sum (k-1)*C_i fits B*C minus overhead. If the next case does not fit, stop; do not skip to cheap later cases. Insufficient overhead budget selects none, budget infeasibility explicit. No outcome-dependent stop or measured-rollout-length cutoff.
Report selected case count/fraction, all four labels, precision, rescues found/recall, regressions induced, net rescues-minus-regressions per population case, planned cap cost and actual offline counterfactual NFE using recorded chosen-arm chunk counts plus declared probe overhead. The actual cost is descriptive after selection, never used to choose cases. Also report actual study NFE including two probes on every scored arm. Comparator overhead is a transparent standalone accounting model; all recorded experiments include the same two-evaluation probe and head. Head/prefix time is separate and no FLOP equivalence asserted. Include equal-overhead comparator sensitivity. No threshold is selected from validation.

## Uncertainty and decision gate
10,000 paired cluster-bootstrap replicates, seed20261005. Standard clusters are task identities; Plus primary clusters base family within suite, with condition-cluster sensitivity. Resample clusters with replacement; rerun ranking, budget capacity, tie handling and metrics for each replicate. Report percentile95% intervals, undefined-replicate counts; if >5% undefined for a gate metric, gate is inconclusive. No episode-wise confidence claims. Report by task/family/axis/severity descriptively with denominators, without selecting a winning subgroup.

Only primary k=4, B=75% is eligible for the decision gate. Each benchmark must have at least ten rescues and ten regressions overall; at least ten selected rescues across five distinct primary clusters; selected precision≥10% and rescue recall≥20%; lower95% cluster bounds >0 for precision-minus-prevalence and selected(net rescues-minus-regressions)/N, and >0.5 for rescue-versus-regression AUROC. Both benchmarks must pass to propose a general closed-loop test. Missing/inadequate evidence is inconclusive and means STOP, not permission to tune. Other counts/budgets/sigma/metadata/sensitivities cannot rescue a failed primary gate. No adaptive controller is built. A passing ranking gate only supports proposing a separately declared closed-loop test with a rule frozen on this validation set and fresh test cases.
